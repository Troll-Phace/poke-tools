# poke-tools project profile

Local Python 3.12/uv and SQLite MCP server for team building in HeartGold/SoulSilver and Emerald; this is the original Troll-Phace/poke-tools repository, not the separate Claude fork. Application files are in `src/poke_tools/`, data and generated SQLite state in `data/`, tests and evals in `tests/`. [Architecture](ARCHITECTURE.md), [data provenance](DATA_SOURCES.md), and [Cherry Studio setup](CHERRY_STUDIO_SETUP.md) are existing references.

- Plan: [root PLAN.md](../PLAN.md). Progress: [shared existing ledger](../.claude/state/progress.md). The Codex overlay does not transfer, reopen or close any phase.
- [framework.json](../framework.json) defines locked, no-sync lint/format/pytest against an existing uv environment. The uv flags prevent dependency resolution from contacting upstream. Default tests/verify deselect the three existing live Bulbapedia evals; run the separate tests_live command only with scoped access when a phase requires that evidence. Preserve this separation if new external cases are added. Provision a missing environment only with task authorization. Before a product gate confirm the intended SQLite fixture is available and the relevant suite did not skip; do not claim a green eval if database-backed cases skipped. A real refresh is a separate, networked product acceptance check, not a harness test.
- MCP runs over stdio. The logged Cherry Studio setup pins Python 3.12 in the client and sets the intended database path. Preserve the live agent acceptance gate and output/coverage constraints in the project plan.
- Codex uses its own `.codex/` and `.agents/`; Claude settings, hooks, agents and permissions are unchanged. The shared ledger’s path does not import Claude permissions. No UI/front-end role or design-system scaffold applies to this server.
- Dedicated planning is Astra/low; the orchestrator inherits per chat. Model and effort for backend-dev and test-engineer are **pending user choice**; do not dispatch either role with an inherited default. Reviewers and triage agents are not implementors.
- Configured hooks are portable on Git-root POSIX shells; run the validator/helper tests on this host. Use the modern Codex binary bundled with the ChatGPT app for that pilot; this Mac's unrelated PATH Codex 0.1 CLI does not support the same controls. Actual skill/agent discovery, repository hook trust and native lifecycle delivery require an interactive pilot; do not auto-approve hooks. No authenticated GitHub integration was exercised during scaffold setup.
