# Testing

Use the non-watch pytest, Ruff lint, and Ruff format-check commands in [framework.json](../../framework.json); report the exact command, code, and counts. Exercise the relevant MCP stdio behavior for application changes. Verify whether the database-backed cases ran and report needed environmental setup rather than passing skipped acceptance. For evals distinguish YAML case entries from collected pytest nodes. The default tests and verify commands omit exactly three opt-in live Bulbapedia cases; use tests_live when permitted and required by a phase, and report those results separately. The regular suite still constructs an HTTP client without sending a request; in a SOCKS-proxied environment that check needs a supported SOCKS transport. Keep live Cherry Studio and upstream refresh evidence separate from offline/harness evidence. Validate harness configuration with `python3 scripts/framework/validate.py --configured` and run `python3 -m unittest discover -s tests/framework`.
